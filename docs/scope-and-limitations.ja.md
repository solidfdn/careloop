# 実装範囲と制約

[ホーム](../README.ja.md) · [English](scope-and-limitations.md) · [試用ガイド](demo-guide.ja.md)

## 実装済みのデモ

CareLoop v0.5.2 RC32は、デモ用に作成した300人の一覧から始まります。担当者は検査結果の送付が遅れている患者や予約日に来院しなかった患者を見つけ、根拠となる資料を読み、次の対応を登録して患者に返信できます。患者は返信を読み、説明を希望する内容を伝えられます。PDFの登録、紹介先による引受、担当者の確認、報告の訂正に伴う再確認も試せます。

公開アプリはsynthetic-demoモードです。架空データと同梱のPDFで利用してください。実際の患者・医療機関への連絡は行わず、デモ役割の切替は本人や医師資格の確認ではありません。

## 境界

- 診断、緊急度、治療、個々の検査の必要性をアプリが決定しません。
- 原文の記載や確認項目の完了は、実施の事実や報告書の臨床的な十分性を証明しません。
- Geminiが質問の意図を解釈し、渡された記録・原文から対象を選びます。サーバーが値と出典を結び付け、確認時点、情報不足、矛盾、範囲の制約を表示します。回答の不足や関連情報の選択誤りは起こり得るため、参照元を確認します。
- 質問で症例記録を更新したり、終了を承認したりしません。患者役割は担当者向け一覧へ質問できません。
- AIの確認候補には資料と人の判断が必要です。候補ゼロも完備性を示しません。
- 一覧で人数を質問すると、該当する患者を重複なく数え、対応するフォロー記録を開けます。優先度ごとの帯は記録の件数を示します。同じ患者が複数の対応一覧に含まれる場合があり、件数は操作に応じて変わります。本番環境の処理容量は未測定です。
- 施設ごとの経路、臨床的な期限、エスカレーションは個別に定義する必要があります。
- EHR/FHIR、OCR、医療機関への実連絡は、今回のデモに統合していません。
- セッション期限・利用上限で試用が停止する場合があります。本番の稼働率、負荷容量、サービス水準は確立していません。
- 東京への配置とAIのglobal接続は、UAE国内だけでのデータ処理を保証しません。

## 今後の試行

実施設への導入には、施設の確認、本人・権限の認証、データの取扱いへの合意、経路・言語の監修、患者と業務面の効果測定が必要です。臨床・専門家・実利用者による評価は今回の構築範囲外で、検証実績として完了していません。患者の回答は自己申告の記録であり、その機能があることだけで理解の改善を示すものではありません。

目指す価値は、未完了のフォローを見えるようにし、担当者の行動につなげることです。対応完了率、臨床効果、対応までの時間、患者の理解の改善は今後の評価事項です。

# 権限・データ管理・運用

[ホーム](../README.ja.md) · [English](security-and-operations.md) · [構成図](architecture.ja.md) · [検証](validation.ja.md)

公開サービスは**架空データによるデモ**です。以下は保存済みのv0.5.2 RC9実装・公開確認記録と照合した内容です。認証取得や独立した安全性評価を示すものではありません。過去の復旧試験や費用見積は、その時点を分けて記載しています。

## アクセスの境界

| 境界 | 実装済みの制御 | 限界 |
| --- | --- | --- |
| ブラウザのセッション | ランダムなトークンをHttpOnly・SameSite=StrictのCookieで保持。HTTPSではSecure。サーバーはハッシュを保存。 | 個人の本人認証ではない。同じプロファイルのタブは共有。 |
| 作業領域 | 初期例と明示的な300件へのデモ拡張をセッションごとに保持し、症例・資料・処理記録をその範囲に限定。 | 医療機関のテナントや患者の本人確認システムではない。 |
| 操作 | デモ役割ごとの許可をサーバーで確認。 | 医師資格や所属施設の確認ではない。 |
| 更新 | 症例・作業領域の更新番号を照合し、原子的に保存。 | 古い操作は拒否され、読込み直しと再判断が必要。 |
| ブラウザからの要求 | 更新時のオリジン照合、要求サイズ制限。 | 本番認証や侵入試験の代替ではない。 |
| クラウド接続 | サーバーの実行IDを使用し、ブラウザに保存先・AIの認証情報を渡さない。 | 本番の権限・施設間アクセス・配置地域は個別確認が必要。 |

## データと保持

- **原本と抽出**：受理したPDF原本、ページの抽出文、登録した根拠を分離。原本取得は世代とハッシュを照合し、登録には原本比較の確認を要求します。
- **訂正**：旧資料と以前の終了・履歴を保持。新資料で関連する確認が失効し、資料集合の変更で古い候補判断も再確認対象となります。
- **履歴**：デモ上の本人性と連鎖ハッシュを記録。整合性の確認であり、外部に固定された改ざん不能な診療監査保管ではありません。
- **期限**：作業領域は24時間で利用期限を迎えますが、**記録や原本は自動削除されません**。本番の保存期間・削除・本人からの請求への対応は事前合意が必要です。
- **AI**：自然言語の質問では、権限と処理量を限定した記録、集計値、関連履歴、原文を設定済みのGeminiへ送ります。任意の資料確認では現在の資料本文と関連する解消判断を送ります。記録上の配置はVertex AIのglobal接続です。ルールのみの確認ではモデルを呼びません。利用できるのは架空データのみです。
- **回答**：モデルが渡されたIDを選び、サーバーが選択を検証して、表示する値と引用を記録に結び付けます。出典、確認時点、参照範囲の制限を表示します。質問では症例データを更新せず、実行と利用量の記録を別に保存します。患者役割からの担当者向け一覧への質問は拒否します。
- **連絡**：メッセージ・支援希望・引継ぎはCareLoop内の記録です。SMS・メール・予約・医療機関への連絡は送信しません。

## 依存関係と容量

公開構成はCloud Run、Firestore、Cloud Storage、任意のVertex AIです。画面はReact/TypeScript、APIはFastAPI/Python、本文抽出はpypdf、原本表示はPDF.jsです。PDF取込には原本保管先、自然言語の質問とGeminiによる資料確認にはVertexへのアクセスが必要です。OCRは未統合です。

現行の同時処理制御でも参照している保存済みの配置条件は、**1 CPU / 512 MiB、Cloud Run最小1・最大2インスタンス**、リクエスト単位課金、HTTPによる起動確認です。PDF・AIの重い処理はサービス全体で同時1件に制限され、インスタンスを増やすだけでは解除されません。

| v0.5.2 RC9ソース上の上限 | 作業領域・要求ごと | サービス累積設定 |
| --- | --- | --- |
| 作業領域 | 24時間・成功更新100回 | 作成250件 |
| PDF取込 | 3回・合計20 MB。1件10 MB・20ページまで | 500回・2.5 GB |
| AI質問・資料確認の共通枠 | 8試行・入力合計200 KB。1回32,000バイトまで | 1,200回・入力25 MB |
| PDF原本取得 | 30回・100 MB | 1,500回・12 GB |

設定上限であり、現在の残量、同時利用者数、サービス水準の保証ではありません。失敗や自動再試行でも予約枠を消費する場合があります。質問回答はサーバー処理70秒以内、最大2試行です。再試行の範囲を制限するもので、回復成功の保証ではありません。期限切れ・再起動で累積枠は戻りません。制限回避のために作業領域を繰り返し作らないでください。

### 障害時の扱い

| 状況 | 対応 |
| --- | --- |
| 更新競合 | 最新の症例を読み直し、確認してから操作する。 |
| 読めない・暗号化・上限超過PDF | 取込を拒否。OCRへの自動置換や未確認本文の登録はしない。 |
| PDF保管・整合性確認の失敗 | エラーを示し、登録成功や未確認の原本として表示しない。 |
| 質問の時間切れ・不完全な選択・回復対象の接続エラー | 残り時間と利用枠があれば再試行。回復できなければエラーを示し、症例記録を保持。 |
| 回答中の記録変更 | 古い回答を拒否し、現在の記録への再質問を求める。 |
| 資料確認での不正なAI応答 | エラーを示し、候補ゼロの正常終了に置き換えない。 |
| 利用上限・期限切れ | 記録を保持して対象処理を止める。画面の案内に従うかSOLIFANへ連絡する。 |

過去のv0.4.10では、隔離環境へのアプリ記録・原本世代の復旧を確認しました。新規クラウドプロジェクトへのIAM・課金・DNSを含む全面切替ではありません。公開デモの稼働率・災害復旧目標は検証していません。

### 費用の前提

**2026年11月2日の保存済み計画見積**は、上記の小規模構成、低利用の審査1か月、追加AI1,000回と保管・ビルド等の予備を前提に、**20〜35米ドル（税・クレジットを除く）**です。過去の計画値であり、現行価格の見積、請求額、支出の自動停止保証、本番の患者単価ではありません。費用要因は稼働・待機計算資源、DB処理と履歴増加、原本・通信、ビルド・ログ、モデルのトークン数です。新たな運用判断では料金と実使用量の確認が必要です。アプリの回数・予約枠はクラウド全体の請求上限ではありません。
